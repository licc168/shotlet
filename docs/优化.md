# Shotlet 优化清单

原稿是一份代码审查，按 P0 / P1 / P2 排列。这里只做了排版，没有改问题描述，也没有另加新的优化项。

状态对照的是当前 `main`：`17d2a6a`（与 `origin/main` 一致）。「已修」表示这条里点名的问题在当前代码里已经收掉；「部分」表示只收了一截；「未做」表示还在。

## 当前进度

### 已修

- 主线程重入：`on_main_wait` 发现已经在主线程就直接执行，不再排队后再阻塞等待。
- 录制：ffmpeg 使用 `-loglevel error`，stderr 有单独线程排空；取消使用独立的 `cancelled`，不再走完混音再落盘；`Recorder` 有 `Drop` 清理。
- 历史索引：只有文件不存在才当空列表；损坏的 `index.json` 会备份成 `index.json.broken`；读写走 `RwLock` 内存缓存。未标注图用硬链接写 `{id}.png` / `{id}.base.png`，不再存两份像素。
- 遮罩复制：`finishCopy` 在 `finally` 里复位 `copying`；`dropFrame` 会清掉复制、滚动和未完成的动画帧。
- 多段马赛克：不再在每条开始时清整张画布的 alpha。
- 编辑器：加载图片的 effect 依赖是 `[]`，卸载后不再回写。
- OCR：比较器改为先比精确的 top、再比 x。同一行的容差放在比较器外面。
- 待机轮询：遮罩没开时 `follow_loop` 挂在 `Condvar` 上，不再每 16ms 醒一次。
- 冻结帧：遮罩关掉后会丢掉内存里的预览像素；`freeze-*.shot` 一类临时文件会在淘汰和启动时清。
- 滚动拼接：长图按行 `extend_from_slice`，不再为每次拼接整图逐像素拷贝。与位移无关的 `self_diff` 重算已经不在。
- 一批原先堵在界面线程上的命令改到 `spawn_blocking`。在访达里定位文件改为 `reveal_item_in_dir`。读图有扩展名和 80MB 上限，PNG 尺寸只读文件头。
- 死代码：`watch_shown`、`scroll_mac.m`、`src/App.css` 已经不在仓库里。

### 部分

- 显示器枚举有 `monitors_cached()`，抓屏路径里仍有几处直接 `Monitor::all()`。
- 保存对话框放进了阻塞线程，但贴图打开仍会等窗口 `ready()`。
- `i18n.tsx` 和 `Home.tsx` 卸载时会调用已经拿到的 `unlisten`。监听的 Promise 若在卸载之后才返回，这次监听还是会漏掉。`Pin.tsx` 用了取消标记，这两处没有。

### 未做

- macOS 全局快捷键：`tap_callback` 仍在系统按键回调里抢 `STATE` 这把锁；`apply_now` 持锁期间仍可能做同步文件读写。
- `overlay_mac.m` 里仍有 `setFrame`。遮罩摆放是否还在重复枚举全部窗口，这份清单没有再量。
- 前端仍走 JSON Base64。没有标注时，`Annotator.tsx` 保存 / OCR 仍会 `renderPng` 两次。
- `Annotator.tsx`：拖拽没有按帧合并，仍会读布局并 `getImageData`；`keydown` 的 effect 没有依赖数组。
- `Overlay.tsx`：放大镜仍每帧读 1×1 像素并 `setCursor`。
- `History.tsx`：历史图没有懒加载，搜索没有防抖。
- `App.tsx`：各个窗口仍同步加载全部视图，没有 `React.lazy`。
- `Pin.tsx`：右键菜单只有打开，点空白不会关；滚轮每次直接发缩放。
- `api.ts`：每次调用仍动态 `import` 已经在文件顶部引入过的 `invoke`；`loadImage` 仍在 60 秒后 `revokeObjectURL`。
- 权限：`tauri.conf.json` 的 `assetProtocol.scope` 仍包含 `$HOME/**`；`capabilities/default.json` 仍是 `"windows": ["*"]`。
- 前端 `package.json` 仍依赖 `@tauri-apps/plugin-opener`。Rust 侧的 opener 还在用，不能跟着卸。
- `npm test` 没有 `--experimental-strip-types`。`README.md` 仍写 Node.js 18+，当前机器是 Node 22。

## 一、P0：高危 Bug、死锁与数据丢失隐患

建议优先修。

### 1. 主线程重入死锁：`open_recording` → `open_recorder`

- 状态：已修
- 位置：`open_recording` → `open_recorder` → `on_main_wait`

`open_recording` 在 `ui::on_main_wait` 的主线程闭包里调用 `ui::open_recorder`，而 `open_recorder` 内部再次调用 `on_main_wait`（`run_on_main_thread` + `mpsc::recv_timeout(2s)`）。在 macOS/tao 这种主线程异步队列上，主线程会自己堵住，2 秒后超时报「界面线程没有响应」。

优化：闭包里直接调用 `present_recorder`，或让 `on_main_wait` 发现当前已经在主线程就直接执行。

### 2. 长录制时 ffmpeg 管道死锁，取消也没有真正取消

- 状态：已修
- 位置：`spawn_ffmpeg`、`record_mp4`、`cancel`

`spawn_ffmpeg` 把 stderr 接成管道，又没有 `-loglevel error`，录制过程中谁也不读 stderr，结束才 `wait_with_output()`。ffmpeg 大约每 0.5 秒写一条进度。管道缓冲（大约 64KB）写满后，ffmpeg 堵在写 stderr，不再读 stdin，`stdin.write_all` 就永久死锁。录制上限是 60 分钟。

`record::cancel()` 和 `finish()` 共用一个 stop 标志。取消仍会做完整的 `mux_audio` 并把视频存下来。`Recorder` 和 `AudioCapture` 也没有 `Drop` 清理。

优化：加上 `-loglevel error`，用轻量线程把 stderr 尾缓冲排掉。另加 `cancelled: Arc<AtomicBool>`，取消时跳过混音并删掉临时文件。

### 3. `index.json` 可能被静默清空，读写还有竞态

- 状态：已修
- 位置：`load_all`、`list`

`load_all` 遇到任何 I/O 或 JSON 错误都返回空 `Vec`。一次临时读失败（例如 Windows 上文件被占用）或 JSON 损坏，下一次写入就会用空列表覆盖 `index.json`，历史索引全部丢失。`list` / `export` / `editor_source` 读的时候也没拿 `index_gate()`，和写入、清理抢同一份文件。

优化：只有 `ErrorKind::NotFound` 才返回空数组，其他错误往上抛，并备份损坏文件。用 `RwLock` 保护读写，内存里缓存解析结果。

### 4. 遮罩复用后第二次复制失效，马赛克互相擦掉，改设置会清空编辑器

- 状态：已修
- 位置：`Overlay.tsx`、`draw.ts`、`Editor.tsx`、`ocr_mac.m`

`finishCopy` 成功后没有把 `copying.current` 设回 `false`。`dropFrame` 也没有复位 `copying` / `scrolling`，也没有清 `raf` 和 `stopDragListen`。遮罩窗口是常驻复用的，第二次直接复制会被 `if (copying.current) return false` 拦住。

`renderScene` / `pixelate` 在实时预览里对每条马赛克都传 `isolate = true`。每条开始时把整张画布 alpha 清零，画第二条就把第一条擦掉。

`Editor.tsx` 加载图片的 effect 依赖了 `[t]`，而 `t` 会跟着设置重建。编辑器开着时改主题或快捷键，会重新拉图，盖掉还没保存的标注、旋转和裁剪。

`ocr_mac.m` 的 `shotlet_join_observations` 用容差判断是不是同一行。这个比较不满足严格弱序，也不可传递。文字呈阶梯排列时，OCR 顺序可能乱，比较器本身也是未定义行为。

## 二、P1：性能、功耗与内存

收益最大的一批。

### 1. 托盘待机功耗和常驻内存偏高

- 状态：已修

`follow_loop` 以 62.5Hz 空转。启动后后台线程每 16ms 醒一次，托盘待机时也先调 `escape_key_down()`，再看 `OVERLAY_OPEN`。遮罩没开时应该用 `Condvar` 挂起，待机不再被定时唤醒。

`preview_cache` 最多留 6 帧未压缩的全分辨率 `RgbaImage`。4K/5K 一帧大约 33–59MB，合计大约 200–350MB 以上。`dismiss_overlay` 关掉遮罩后不释放。遮罩退出后（或稍晚一点）应丢掉过期冻结帧。

临时目录会一直涨。`flush_frozen` 每次写几十 MB 的 `freeze-*.shot`，`save_long` 写 `scroll-*.png`，`publish_pin` 写 `pin-*.png`，都没有删。用久了会到数 GB。缓存淘汰、窗口销毁和应用启动时应清旧临时文件。

### 2. 截屏、录屏、滚动长图的热路径

- 状态：部分。拼接和 `self_diff` 已收；显示器缓存、遮罩摆放、快捷键回调、Base64 和重复编码还在。

录屏和滚动截屏每一帧都重新枚举显示器，并做整屏 alpha 混合（`capture_local`、`capture_rect`）。30fps 录屏和大约 50Hz 的滚动截屏，每帧都 `Monitor::all()`。哪怕只截一块单屏区域，也会新分配一块填零的画布，再用 `imageops::overlay` 逐像素混合。会话内应缓存目标 `Monitor`。单屏直接返回裁剪结果，多屏按行 `copy_from_slice`（`crop_screens` 一样）。

滚动拼接是 O(N²) 拷贝，匹配也有重复计算（`Roll::compose`、`best_shift`、`prepend_rows` / `append_rows`）：

- 每次拼接都重新分配整张长图，再双重循环逐像素拷贝。应一次分配 `width * total * 4` 字节，然后 `extend_from_slice`。
- `alignment_cost` 在每个 shift 候选里重算与 shift 无关的 `self_diff`，大约浪费 66% 的 CPU。`absorb` 还会反复调用 `frames_stable`；失配时为了 `eprintln!` 再跑一遍 `best_shift`。预计算行签名，再从粗到细搜索，可以快很多。

macOS 遮罩摆放（`overlay_mac.m`）每次调用 2 次 `setFrame:display:YES`，最多 5 次 `CGWindowListCopyWindowInfo`。`shotlet_log` 在 Release 里仍无条件做 `kCGWindowListOptionAll` 全窗口枚举，并 `fflush(stderr)`。

全局快捷键（`tap_callback`）在 `CGEventTap` 回调里抢全局 `Mutex`。`apply_now` 持锁时同步写日志；命中快捷键时回调里也直接做文件 I/O。macOS 可能因此判定超时，把 EventTap 禁掉。

主线程和 Tokio 线程被堵住：

- 多个同步的 `#[tauri::command]`（`copy_capture_region`、`write_png_base64`、`read_image_bytes`、`pin_file`）在主线程上做重的编解码和 I/O。`pin_file` 为了宽高把整张 PNG 解码；`write_png_base64` 解码之后又重新编码。
- `scroll_capture` 这类 async 命令里直接 `std::thread::sleep`、`mpsc::recv_timeout`、`blocking_save_file()`，占着 Tokio worker。应改到 `spawn_blocking` 或 `tokio::sync::oneshot`。

IPC 和磁盘各存了一遍：

- 除 `pin_annotated_raw` 外，保存、复制、OCR、历史提交仍走 JSON Base64（大约膨胀 33%，还要多次编解码）。没标注的截图在 `commit_bytes` 里同时写两份一样的 `{id}.png` 和 `{id}.base.png`。
- 没标注时，`Annotator.tsx` 保存或 OCR 会调用两次 `renderPng`，同一张图编码两遍。

### 3. 前端渲染和交互

- 状态：未做

`Annotator.tsx` 拖拽没有用 `requestAnimationFrame` 合并。高刷鼠标每次 `pointermove` 都重渲染整个组件（大约 1041 行），`getBoundingClientRect()` 强制回流，`ctx.getImageData(0, 0, 1, 1)` 把 GPU 管线停住。有马赛克时每帧还会新建 2 个离屏 canvas，再全图 `getImageData` 并在 CPU 上扫。应按帧合并、缓存容器矩形、工具栏用 `React.memo`、复用离屏 canvas。`getImageData(0, 0, 1, 1)` 只在 Windows / WebView2 需要时做。

`Overlay.tsx` 的放大镜每帧 4 次强制回流，再加一次 1×1 canvas 回读。`loadFrozen` 已经拿到原始 RGBA `Uint8ClampedArray`，留着引用就能 O(1) 取色，不必每帧建 1×1 canvas。放大镜位置直接改 DOM `transform`，不要每帧 `setCursor` 把整页重渲染一遍。右下边缘会溢出，左上角小于 8px 时坐标还有偏移。

`History.tsx` 一次渲染全部原尺寸 PNG，没有 `loading="lazy"`、`decoding="async"` 或虚拟滚动。搜索框每次击键都直接发 IPC，没有防抖。

`App.tsx` 里每个贴图窗、遮罩窗、录屏边框窗都同步解析 8 个视图。用 `React.lazy` 按路由拆，或在 Vite 里把常用的 overlay / pin 拆成单独 chunk，窗口冷启动会快一些。

## 三、P2：权限、边界和工程体验

### Tauri 权限和路径校验过宽

- 状态：未做。`reveal_item_in_dir` 和读图的大小、扩展名检查已经落地，scope 和窗口权限没有收。

`tauri.conf.json` 里 `assetProtocol.scope` 是 `$HOME/**`，任意 WebView 都能读用户主目录。`capabilities/default.json` 把权限授给 `"windows": ["*"]`。

`read_image_bytes`、`write_png_base64`、`reveal_path` 都没有路径白名单。`reveal_path` 走 `open_path` 时可能直接运行可执行文件，而不是在文件管理器里定位，应改成 `reveal_item_in_dir`。

### 前端交互

- 状态：未做。监听泄漏只修了一半，见上面的「部分」。

`Pin.tsx`：右键菜单打开后没有关闭逻辑，点空白不会消失。滚轮缩放建议按帧合并，避免 IPC 打满。

`i18n.tsx` 和 `Home.tsx`：异步 `onEvent` 没有卸载取消标记。React StrictMode 下监听会漏。

`Annotator.tsx`：`keydown` 的 effect 没有依赖数组，每次渲染都解绑再重绑。

`api.ts`：文件顶部已经静态导入 `@tauri-apps/api/core`，`call()` 里却又 `await import(...)`。`loadImage` 用 60 秒定时器释放 Blob URL，编辑器打开超过 1 分钟后图片会失效。

### 测试和死代码

- 状态：死代码已清。测试脚本和 README 的 Node 版本说明还没改。前端的 `@tauri-apps/plugin-opener` 也还在。

`npm test` 在 Node 22.14 上跑 `.ts` 测试会报 `ERR_UNKNOWN_FILE_EXTENSION`，因为没传 `--experimental-strip-types`。这和 `README.md` 写的 Node 18+ 不一致。

可删的死代码：`capture_session::watch_shown`、被编译链接但从未调用的 `scroll_mac.m`、`shotlet-image` 里没用到的旧滚动对齐函数、`src/App.css`，以及前端没引用的 `@tauri-apps/plugin-opener`。

## 建议的落地顺序

原稿建议分三批：

1. 止血：主线程死锁、ffmpeg stderr 死锁和取消行为、`index.json` 被空列表覆盖、`finishCopy` 复位、多段马赛克互相擦除、改设置导致编辑器重载。这批已经落地。
2. 体感和能耗：`follow_loop` 改 `Condvar`、清 `freeze-*.shot` / `pin-*.png`、退出时释放像素缓存、主线程阻塞命令挪走、标注和遮罩的高频渲染、历史页懒加载。前半已经落地；标注、遮罩放大镜和历史页还没做。
3. 深度性能和安全：录屏 / 滚动缓存 `Monitor`、O(N) 拼接、收紧 `assetProtocol.scope` 和 window capabilities、按视图拆包、二进制 IPC。拼接已经改掉；权限、拆包和二进制 IPC 还没做。快捷键回调里的锁和文件 I/O 也还在，它比这一批里的其余项更容易把快捷键弄丢。
